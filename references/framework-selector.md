# Framework Selector

Use this reference after initial evidence review and before Gate 2. The goal is to make framework use explicit, narrow, and auditable.

## Selection Record

Record this block in `research_brief.md`; for strict or restartable runs, also mirror it in `run_manifest.json`.

```text
Primary lens:
Selected framework:
Why this framework fits the decision:
Evidence prerequisites:
Supporting lens or framework, if any:
Rejected frameworks:
Where it appears in report:
```

## Selection Rules

- Pick one primary lens first, then one concrete framework only if it helps answer a decision-relevant subquestion.
- A framework is allowed only when the evidence package contains or can reasonably retrieve the inputs it needs.
- Reject frameworks that would create template sections without changing the answer.
- Use a supporting framework only for a distinct subquestion, and name the boundary between the primary and supporting work.
- If no classic framework fits, use the selected lens as a reasoning guide and say that no named framework was used.

## Common Fits

| Decision need | Candidate framework |
|---|---|
| Market size or reachable opportunity | TAM/SAM/SOM, bottom-up sizing, scenario ranges |
| Macro, policy, or regulatory exposure | PESTLE, risk register |
| Industry attractiveness or profit pool | Five Forces, value-chain analysis |
| Peer comparison or positioning | Positioning matrix, moat assessment, capability benchmark |
| Company or portfolio priority | BCG matrix, value-chain gap, risk matrix |
| Strategy or option choice | MECE issue tree, hypothesis test, recommendation chain |
| Evolution or path dependence | Timeline, phase model, cross-section comparison |
| Qualitative evidence synthesis | Theme map, contradiction table, evidence saturation note |

## Guardrails

- Do not auto-run SWOT, PESTLE, Five Forces, TAM, BCG, issue trees, and positioning maps together.
- Do not calculate market size if inputs are weak; present a range or gap instead.
- Do not use Porter, SWOT, or BCG as decoration. Each section must change a conclusion, recommendation, or risk view.
- In the report, name the framework only where it clarifies reasoning. Avoid turning the report into a framework textbook.
