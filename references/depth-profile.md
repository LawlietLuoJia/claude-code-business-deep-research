# Depth Profile

Use a depth profile during framing to match research effort to the user's decision need. A profile is a planning hint, not a rigid process mode.

## Profiles

| Profile | Use When | Evidence And Verification |
|---|---|---|
| Brief | The user needs orientation, meeting preparation, or a first-cut view | Use obvious primary or high-authority sources where available, keep gaps visible, and avoid exhaustive verification |
| Standard | Default commercial research for product, market, competitor, company, or topic decisions | Cover each material subquestion with the strongest available sources and record weak-data areas |
| Deep | High-materiality, disputed, regulatory, due-diligence, restartable, or explicitly auditable work | Use stricter verification for material claims, contradiction checks, and stronger delta searches; load `strict-verification.md` when claim-level auditability is needed |

## Rules

- Select the profile in `research_brief.md` and state one reason.
- Do not bind profiles to fixed source counts. A few primary sources can beat many weak secondary sources.
- Increase effort only when the decision risk, uncertainty, or user request justifies it.
- If the user asks for a quick view, do not force the full two-gate deep-research path unless the risk is high.
- If a Brief run finds a decision-critical gap, say what deeper run would be needed instead of pretending the brief can answer it.
